# Contributing

Thanks for your interest in this project. The skills in this repo are designed to help generalists pivot into AI safety — if you've used them, found something wrong, or want to add to them, we'd genuinely like to hear from you.

We're not actively soliciting code or content contributions while the suite is in early release. We're still learning what works, and editorial coherence across the skills matters a lot during this phase. But feedback and corrections are very welcome.

## What's most useful

In rough order of usefulness to us:

**Bug reports and corrections.** If something in a skill is outdated, factually wrong, or links to a dead resource, please [open an issue](https://github.com/ais-skills-collective/ais-skills-for-generalists/issues/new). Particularly valuable: closed fellowships, retired roles, broken links, or factual claims that no longer hold.

**Feedback on whether the skills helped.** If you tried a skill for something it should have been good at and it fell short, that's useful signal. We'd rather hear "I asked X and Claude's answer was generic" than not hear it.

**Content suggestions.** If you know of a resource, organisation, funder, or programme that's missing from a skill and should be included, open an issue. Tell us what's missing and why, and we'll evaluate whether to add it.

**Ideas for new skills.** If you think another skill would be useful, open an issue describing the gap it fills before investing time in drafting one. We're cautious about adding more skills than the suite needs.

## How to file a good issue

A useful issue has three things:

- **What you were trying to do** — the pivot question, task, or query you brought to Claude
- **What Claude said** — paste the relevant bit of the response, or describe it
- **What you expected instead** — the gap, the missing context, or the wrong fact

You don't need to suggest a fix. Naming the problem clearly is more valuable than proposing a solution.

## Pull requests

We may accept pull requests, but please **open an issue first** to discuss what you want to change. This saves you time — we may already be working on it, may have decided against it, or may want it shaped differently than you'd naturally do it.

PRs without a prior issue are likely to be closed without merging.

## Code of conduct

Be kind, be specific, assume good faith. We're all trying to figure this out.

## Contact

For anything that doesn't fit an issue, you can reach the maintainers via the contact details in [AUTHORS.md](AUTHORS.md).
